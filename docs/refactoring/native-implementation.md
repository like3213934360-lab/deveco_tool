## 版本与边界

新动作契约版本为 2。历史 v1 流程原文不自动改写；原有点击、输入、单键、触摸与断言继续读取。鼠标、焦点输入、方向 fling、键组合与持久窗口范围要求 v2；不将 v2 动作降级为点击，不裁剪键组合。历史录制继续使用其捕获版本，新增扩展动作需新建 v2 录制。录制控制与回放共用同一原生命令构造器。公开的动作支持清单标记适配器已实现，真实设备支持和业务效果仍必须实际观察。

保存的文本仅为变量引用；实际值由调用方在运行时提供并由既有私有 payload/effect 存储加密。密码控件不能退化为文本值选择器。已知日志秘密在持久化之前替换，当前采集器累计最多 4096 项、8 MiB，超限在本次输入动作之前拒绝；截图仍需宿主判断，不宣称自动脱敏。

`verify_ui`、flow 最终断言和 `ui_test.check` 已通过现有 `VerificationService` / `DeviceService.verify` 及 `UiReviewService` 复用原生断言、截图制品、读取 token 和宿主评估。结构化断言通过只证明保存的断言；图像读取回执只证明该图被读取，不证明自然语言需求完整或视觉判断正确。

连续日志保持 `complete:false`、`system_delivery:unknown`。边界包括注册前、断连、MCP 停止、未知进程代际、未校验尾部及存储限制。第一条完整归属行再次核验且落盘后才 ready。旧区间日志仍是有界样本，不能同连续分块拼接后宣称系统无损。超过 gap 清单上限仅累计 omitted_gap_events，不把它换算成丢失日志行数。采集器结束后恢复需重新确认进程、时间和就绪状态。

默认启动检查只观察有限时间，非纯色画面也不是业务正确性证明。热更新 PID 清单的保存证明仅限观测到的 PID 集合，不能检测观测之间的 PID 复用。模拟器命令接受和应用 UI 对该变化的断言继续分离；物理传感器效果、多显示器与未配备 SDK 平台保持未验收。

热补丁接受回执的 `artifacts` 保留本次 `prepared.patches` 中实际上传且设备摘要核对通过的捕获制品描述，包括路径、SHA-256、制品 ID 和字节数。正常返回和补丁已接受但后续启动观察失败的回执都携带相同描述，供统一证据封存、制品复核及部署关联使用；此关联本身不将后续观察失败改为通过。
