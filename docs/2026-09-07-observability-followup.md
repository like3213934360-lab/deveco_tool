# 2026-09-07 重启后日志缺口修复

这次处理 MCP 的构建诊断、性能日志和摘要示例，不修改应用业务代码。与上午的 UI 状态、快照及 HDC 环境修复一起提交。

## 构建错误输出

官方 CLI 1.3.1 的顶层异常处理会在 console.error 后立即 process.exit(1)。当 stderr 是管道时，大块输出尚未排空就可能退出。用同一退出模式复现：约 2.25 MB 输出仅收到 65,536 字节，末尾编译错误缺失。加入子进程专用 preload 后收到 2,250,078 字节，末尾错误保留，退出码仍为 255。这证明了该丢失机制；历史三次构建没有底层原始管道副本，不能证明每次丢失的全部细节。

`deveco-cli-output-runtime.mjs` 仅在构建/清理 CLI 子进程加载：显式退出前等待 stdout/stderr 排空，最多 2 秒；保留原请求的退出码。通过独立的小回执向父进程报告 drained、natural、timeout 或 error。取消、异常退出或回执缺失显示 unknown，排空不完整不能被判为构建成功。退出后清除回执；不改 node_modules 或宿主进程的 process.exit。

失败或缺少成功确认的构建即使不指定 log_path，也保留捕获日志。构建响应给出保存路径及输出完整性状态。状态只描述 CLI 已输出的内容，不宣称能恢复编译器未输出的信息，也不会为了诊断而自动重建项目。256 KiB/流的内存尾部限制与响应摘要限制不截断保存文件；原有 128 MiB 文件限制仍生效。

## 独立性能日志

四个已观测的顶层 UI 操作在返回前独立记录成功/失败，嵌套内部操作不重复记录。默认目录 `~/.deveco-tool/logs`，可通过 DEVECO_TOOL_LOG_DIR 指定，DEVECO_UI_PERFORMANCE_LOG=0 可关闭。日志含时间、sessionId、PID、operationId、阶段、CPU/内存和错误码，不含工具参数、UI 文本、图片或错误详情。

每份 5 MiB，最多 5 份，进程内串行、跨进程文件锁协调轮转；单条记录也有上限。日志不可写时保留原 UI 结果，返回 performance.log.status=failed 并限频输出 stderr 提示。写入时间单列，不混入操作耗时；不承诺断电持久性。

新启动的 stdio MCP 服务在 macOS 真机上完成 12 次只读调用（11 成功、1 次预期的缺失快照错误），独立日志恰好 12 条，operationId 全部唯一。其中 9 次故意丢弃返回值，仍全部留存。现场新抓树 1069 ms、截图抓树 1105 ms，快照复用 0.73–1.41 ms；两条已检查的落盘耗时为 3.97 ms 与 1.74 ms。截图内联后的临时文件确认删除。不同页面不能据此计算相对上午基准的提升率。

## 诊断示例

摘要按编译错误、SDK 兼容、弃用、依赖打包和 sourceMaps 顺序展示，分别预留 3/3/2/1/1 个示例。相同位置、消息的重复样例不再占用名额，计数仍是诊断行数。支持 ArkTS Error Message / At File 以及原生编译器的文件、行列定位。

历史日志回放确认：1836 条弃用警告后，83 条 SDK 警告仍保留 3 个位置示例；真实 ArkTS 的 woc 错误和 C++ 的 Clamp01 错误均以位置进入摘要。部分历史 log_path 被其他构建覆盖，回放采用仍保留错误的直接构建日志和原生错误日志，不把覆盖后的文件当作原始失败样本。
