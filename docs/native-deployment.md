# 原生构建和包集合部署

执行协议为 `native-6`，使用新的状态目录；没有旧单包参数别名或历史状态解码器。

`workflow_run.start` 的 `app_deploy` 输入示例：

```json
{
  "action": "start",
  "workflow": "app_deploy",
  "request_key": "install-review-1",
  "input": {
    "packages": [
      { "path": "/absolute/entry-signed.hap" },
      { "path": "/absolute/shared-signed.hsp" }
    ],
    "target": "device-id",
    "app": {
      "bundle_name": "com.example.app",
      "module": "entry",
      "ability": "EntryAbility"
    }
  }
}
```

每个包可提供 `sha256`。提交时顺序流式复制 1–64 个包到任务制品，固定摘要；等待设备租约后重新校验。部分捕获失败会释放此前的临时副本，并发重复提交会释放未绑定的副本。包集合必须属于同一应用版本、模块名称不重复、类型和扩展名一致，并且能唯一定位启动 Ability。

部署工作流将单包或多个包传输到本次操作独占的设备目录，逐个核对设备端 SHA-256，再通过一次 `bm install -p` 提交安装，使 HAP/HSP 依赖同时可用。目录身份绑定状态目录、任务、节点、设备及捕获包的摘要、大小和扩展名。不会把多个主机路径传给 HDC 后误记成一次原子安装。传输未确认或摘要不符时不开始安装。

安装和启动各自保存操作回执。安装完成但 HDC 响应丢失时，恢复只读取已登记命令的回执，不重新传包或再次安装；不能用设备上已有同名应用作为本次安装完成的依据。安装命令状态不明时保留设备临时目录和资源保护，等待核对；规范化回执提交到本地 SQLite 后才清理远端目录。准备阶段尚无安装操作登记时，可重新传输本任务捕获的包并重新核对摘要；一旦有安装登记，就只走回执核对路径。准备阶段真实中断仍需专项验收，不能据此宣称所有部署中断均可自动继续。

工作流中的启动命令增加设备端固定回执，绑定任务、节点、设备及完整 Want 参数摘要。宿主响应丢失后只读取已登记操作；收到匹配的完整回执，才继续进程检查及后续断言。设备端已有登记但缺少完成回执时，禁止重新启动，并阻止其他任务抢占设备。已确认命令结束但被拒绝的结果保存为失败，不作为不确定操作保留，也不会在恢复时重新执行；这不表示撤销已发生的副作用。该机制已接入部署的安装和启动、声明路由和录制启动。流程逐步操作分别保存准备输入、设备操作及步骤结果，已完成步骤读取记录；真实中断的覆盖边界继续单独验收。

安装恢复回归使用真实 POSIX 回执脚本和替代的 `bm`、`aa` 命令：单包和三包分别覆盖成功、拒绝、响应丢失、重开 SQLite、后续启动、设备竞争、取消及目录清理；设备端摘要不符也会阻止安装。这些测试不代替真实签名包安装恢复验收。

`project_build` 默认根据任务选择模块类型：`assembleHap` 选择 entry/feature，`assembleHar` 选择 har，`assembleHsp` 选择 shared。显式指定不支持任务的模块会报错。HAR 由 Hvigor 按依赖编译，不作为设备安装包。

工作流中的 OHPM 安装、Hvigor 同步和各次构建分别保存完成记录。只有受管进程和输出流确认关闭后，才把规范化结果与输出文件摘要提交到 SQLite；然后向工作流节点返回。宿主在此后、图节点提交前中断，可以核对记录继续，已完成的命令不再执行。构建失败的早期诊断也会保存，大结果放入制品。细节和边界见 [命令恢复](native-command-recovery.md)。

`build_deploy_verify` 构建所选 HAP，从实际编译包的 `module.json` 读取共享依赖，继续构建本产品的 HSP 及其传递依赖，随后捕获签名包。外部共享 bundle 或缺少本产品源码的依赖会明确报错；不推测其安装状态。

同步是独立图节点，各次 HAP/HSP 构建有独立命令记录；后续构建更新工程模型不会要求重跑已完成的同步节点。热重载应用仍由会话服务核对，不能通过重复调用构建命令恢复热补丁。

当前运行摘要 `23758f48`、编译摘要 `25b0b62c` 的真实 SDK/手机验收通过 23 项：四模块（entry/feature/HAR/HSP）、default/tablet 双产品、默认任务筛选及 HSP 依赖补全；两个产品各自完成个人签名三包安装，在实际安装后注入响应丢失，重建 Runtime 后均读取既有回执继续，安装各派发一次，最终 `libraryshared` UI 断言通过。此项复用已有个人资产，不包含新云端资产创建，也不等同于安装过程的 OS 强杀。原始目录为 `20260908-native6-multimodule-performance-dev4-1`。

迁移复核发现旧 `start_app.target` 和 `apply_changes.target` 表示构建目标，不能映射为新版的 HDC 设备 `target`。当前工程解析选择产品下的 default 或唯一适用目标，显式选择其他构建目标的入口仍待补齐。迁移矩阵已将这两个参数恢复为 pending；默认目标的签名包集合验收不代替这一场景。
