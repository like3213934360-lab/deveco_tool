## 最终录屏与保留的失败

用户解锁同一台 USB Mate 80 后，最终构建重新录制并取回 **989,999 字节** MP4：H.264 **868×1920、220 个实际解码帧、3.693 秒**，AAC **179 帧**，容器 3.819 秒。严格检查四次进程调用全部退出 0，stderr 为空；保留源时间基、全部音视频解码、空输出拒绝等条件。原视频前后 SHA-256 一致：`6e30582bda93c1dd15fada53aa4b6e4aaccc303a01f61f87a3001b2e7e8939e6`。最后 record_status 为 idle，无待取回文件。

以下失败不从历史记录抹除，也不计为通过：

1. 新 HSP 测试夹具缺少 SDK 要求的 deliveryWithInstall/installationFree 字段，已补齐夹具后重新通过真实构建；没有降低 SDK 检查。
2. 新目录门禁先发现旧编译缓存，再暴露过宽的源码路径判断及上游片段夹具不是完整可执行模块的问题。删除缓存、锚定路径、只排除片段的可执行 import 解析后重新通过；片段语法检查仍保留。
3. 最终录屏首轮被系统锁屏以 10106102 拒绝；解锁后首次重试因失败启动保留的会话收到 CONFLICT。先用正式 record_stop 确认图库不存在视频，再明确 discard 该次会话记录后新录制成功；没有删数据库、清图库或忽略冲突。中间构建的另一段成功视频单独保留，不冒充最终结果。
4. 查询失败会话时尝试的 mediatool 不在 MCP 只读 shell 白名单，收到 INVALID_INPUT。保留该拒绝，改用已有正式录屏 API 核对；没有扩展 shell 权限或增加自动降级。
