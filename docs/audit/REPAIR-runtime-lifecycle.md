## 修复后的构建与启动契约

1. `bin/deveco-mcp.mjs` 为稳定入口。源码目录核对 package/lock、构建脚本、入口和全部 TypeScript
   源码的 SHA-256 指纹，并校验选中产物的全部 JS/source map。源码有变、产物缺失或内容改变时，
   先执行本地构建并重新核验。构建失败就退出，不继续执行旧程序；不自动联网安装依赖。
2. 构建向临时目录写入完整产物，检查构建过程中输入没有变化，再重命名为独立不可变目录，
   原子发布 `dist/current.json`。失败不替换已发布指针。并发构建拥有不同目录，不覆盖彼此的分包。
3. `__DEVECO_BUILD__` 在编译时固定版本与输入指纹。运行中的旧进程持续报告自己的版本，
   不会因磁盘 package.json 更新而改称新版。启动 stderr 与 `doctor.server.build_id` 提供身份依据。
4. 新的宿主注册和 npm bin 使用稳定入口；`dist/cli.js` 是兼容入口，既有配置无需重写也能接受检查。
   所有已运行连接仍需在宿主重载 MCP 后采用新版，不在活动任务中强杀进程。
5. 不再按文件年龄删除任何旧分包。显式回收需先关闭所有使用该目录的连接，再删除 dist、重新构建。
   `prepack` 重新构建，通过 npm 打包规则仅收录当前构建，不删除本地旧进程使用的文件。

校验使用复用的 64 KiB 读取缓冲区，不把整个源码/source map 留为一次性 Buffer。
保留全部完整性校验、3 个运行时依赖、15 个 lazy 工具与原有动作；没有加入后台监控或轮询。
