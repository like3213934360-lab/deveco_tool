# 原生状态容量控制

配置 `max_bytes` 默认 256 MiB。制品、输出流、待删除文件和 SQLite 活跃页面/WAL 参与共享预算，预留量通过 SQLite 写事务在多个 MCP 之间协调。进程输出先预留再写入，超额时停止生产进程；中断后只发布实际存在的字节。

工作流使用官方 SQLite Checkpointer。`BoundedSqliteSaver` 只包装公开的序列化与写入接口，框架仍负责编码、SQL 和恢复。每次写入建立独立的异步预留作用域，序列化完成后、交给官方 SQL 之前，按编码字节数预留主数据库/WAL 页面和索引余量。`putWrites` 的所有行分别计量；单个编码值限制为 512 KiB。节点结果超过 16 KiB（UTF-8 字节）先变为制品引用。

检查点预留不产生临时文件，成功或失败都会删除预留记录。进程突然退出后，状态恢复会回收死亡所有者留下的无文件预留。回归覆盖官方格式往返、异步序列化期间另一个 MCP 抢占容量、批量写入中的超大值与失败回收。

这是一套应用层预算，并非文件系统硬配额。检查点余量是保守预留，尚未证明 SQLite 所有页面分裂的严格最坏上界；数据库空闲页、SDK 写出的临时报告和 LSP 日志仍需继续收敛，不能把当前检查点回归等同于统一磁盘容量验收通过。
