# 原生 SDK 临时文件与日志预算

应用制品、过程输出流、待删除文件、数据库和原生 SDK 临时目录共用 `max_bytes` 预算，默认 256 MiB。申请临时目录前用 SQLite 写事务预留额度；其他 MCP 进程同时看到该预留。没有额度时在启动 SDK 之前返回 `STATE_CAPACITY`。

| 用途 | 单次或单会话预留 |
| --- | --- |
| ArkTS 静态预检 | 16 MiB |
| Code Linter、API 扫描 | 各 32 MiB |
| ArkTS LSP 日志 | 16 MiB；最多四个会话 |
| 密钥与 CSR 生成 | 1 MiB |
| HAP/HQF 签名 | 输入大小的两倍加 16 MiB |

原生工具直接写入专属目录。运行期间每 200 毫秒异步检查一次，遍历最多 4096 个条目、16 层目录，不接受符号链接或特殊文件。超过预算会记入已观察的实际字节数，停止接受新的写入，并取消相应受管操作。SDK 成功退出后还会进行最终检查，超额结果不会发布为成功。

这是预留与观察机制，不是操作系统文件系统硬配额。外部 SDK 在两次检查之间可能突发写入超额内容；文件系统元数据和其他应用的文件也不受该预算限制。不能据此承诺进程所有物理磁盘写入始终不超过 256 MiB。

临时目录的所有权随进程登记持久化。取消无法确认时保留文件和额度，避免清除仍在使用的输入。确认所有相关进程退出后再删除目录并释放预留；重启时也遵循相同规则。清理失败保留记录供后续重试，不静默遗失磁盘占用。

LSP 日志目录按会话创建，SDK 与工程身份不变时复用该会话。调用参数请求 ERROR 级别，但当前 SDK 内部 worker 仍可能使用 TRACE，因此不能只依赖日志级别控制空间。会话关闭等待完整进程退出后回收日志。

`test/native-directory.test.ts` 使用真实子进程覆盖超额写入、取消清理、活跃输入保留、多个存储连接共享预算及启动失败释放。真实 Studio 26.0.0.821 / SDK 26.0.0.105 的 LSP、Linter、预检、API 扫描、密钥与 CSR 验证见 `/private/tmp/deveco-native-sdk-20260908-6/evidence.json`。这不替代其他平台 SDK 或最终长时间运行验收。
