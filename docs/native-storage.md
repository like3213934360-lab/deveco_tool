# 原生状态容量控制

状态库启用 WAL 与 `synchronous=FULL`。自有表、索引和执行协议标记在同一 `BEGIN IMMEDIATE` 事务中创建，避免逐条 DDL 自动提交。协议不匹配或出现多个协议标记时回滚新增表并关闭数据库，不修补其他版本的执行状态。官方 Checkpointer 的表和写入协议仍由官方实现管理。

应用制品、过程输出流、待删除文件、数据库和原生 SDK 临时目录共用 `max_bytes` 预算，默认 256 MiB。申请临时目录前用 SQLite 写事务预留额度；其他 MCP 进程同时看到该预留。没有额度时在启动 SDK 之前返回 `STATE_CAPACITY`。

工作流使用官方 SQLite Checkpointer。`BoundedSqliteSaver` 只包装公开的序列化与写入接口，框架仍负责编码、SQL 和恢复。每次写入建立独立的异步预留作用域，序列化完成后、交给官方 SQL 之前，按编码字节数预留主数据库/WAL 页面和索引余量。`putWrites` 的所有行分别计量；单个编码值限制为 512 KiB。节点结果超过 16 KiB（UTF-8 字节）先变为制品引用。

检查点预留不产生临时文件，成功或失败都会删除预留记录。进程突然退出后，状态恢复会回收死亡所有者留下的无文件预留。回归覆盖官方格式往返、异步序列化期间另一个 MCP 抢占容量、批量写入中的超大值与失败回收。检查点余量是保守预留，尚未证明 SQLite 所有页面分裂的严格最坏上界；数据库空闲页也不计入活跃页预算，不能据此宣布统一物理磁盘容量验收通过。

## MCP 请求日志

普通 `request_start`、`request_finish`、`request_failed` 日志最多缓冲 20 ms，再在单个 FULL 事务中写入。每个 Worker 先在共享状态库预留 64 KiB；缓冲最多 128 条，并按文本内存及行开销计量，达到任一上限就同步刷写。缓冲预留没有对应的制品文件，关闭时刷写并释放，死亡所有者由状态恢复回收。日志记录采集时刻和请求 ID，插入顺序不等于与其他过程事件的发生顺序。

强杀可能丢失最后一个缓冲窗口的普通请求日志。工作流检查点、操作意图、设备回执及进程归属记录继续同步持久化，不经过这个缓冲。批量写入失败会回滚整批、报告错误并阻止后续请求继续执行；关闭时即使日志刷写失败，也会继续清理 SDK 会话及状态库。

## 原生 SDK 临时文件与日志

| 用途 | 单次或单会话预留 |
| --- | --- |
| ArkTS 静态预检 | 16 MiB |
| Code Linter、API 扫描 | 各 32 MiB |
| ArkTS LSP 日志 | 16 MiB；最多四个会话 |
| 密钥与 CSR 生成 | 1 MiB |
| HAP/HQF 签名 | 输入大小的两倍加 16 MiB |

原生工具直接写入专属目录。运行期间每 200 毫秒异步检查一次，遍历最多 4096 个条目、16 层目录，不接受符号链接或特殊文件。超过预算会记入已观察的实际字节数，停止接受新的写入，并取消相应受管操作。SDK 成功退出后还会进行最终检查，超额结果不会发布为成功。

这是预留与观察机制，不是操作系统文件系统硬配额。外部 SDK 在两次检查之间可能突发写入超额内容；文件系统元数据和其他应用的文件也不受该预算限制。不能据此承诺进程所有物理磁盘写入始终不超过 256 MiB。

临时目录的所有权随进程登记持久化。取消无法确认时保留文件和额度，避免清除仍在使用的输入。确认所有相关进程退出后再删除目录并释放预留；重启时也遵循相同规则。清理失败保留记录供后续重试，不静默遗失磁盘占用。

LSP 日志目录按会话创建，SDK 与工程身份不变时复用该会话。调用参数请求 ERROR 级别，但当前 SDK 内部 worker 仍可能使用 TRACE，因此不能只依赖日志级别控制空间。会话关闭等待完整进程退出后回收日志。
