# 原生 Code Linter

`code_lint` 直接使用所选 Studio/CLT 的现代 Code Linter 文件报告协议，不启动官方 CLI，也不修补其文本报告。Studio 使用自带 SDK；CLT 入口接收所选 SDK 参数。CLT 可通过新配置 `java_home` 指定 JDK，详见 `native-toolchains.md`。

## 输入和执行范围

- `project_path`、`product` 固定工程和产品。`path` 默认为工程根目录，也可为其内部文件或目录；不存在的路径、向外跳转及指向工程外的符号链接在启动前拒绝。
- `config_path` 默认为工程的 `code-linter.json5`，允许显式共享配置。调用前校验 JSON5 语法、常用字段类型、文件类型及 1 MiB 上限；不凭配置中出现规则名称就声称 SDK 支持该规则。
- `fix` 默认关闭；开启时取得工程写租约。`incremental` 先验证 Git 工程，再传递原生增量选项。不自动初始化 Git、不自动 clean，不升级 SDK。
- 当前 CLI 模式未设置 `--exit-on`，代码缺陷通过报告表达；任何非零退出码、终止信号或原生控制台执行错误标志均按工具失败处理，即使已经生成部分报告。

## 有界结果和可检查证据

原始 JSON 报告最多 16 MiB、100,000 个问题，完整报告存入制品。响应包含完整数量统计，预览默认 50 条、最大 200 条且不超过 24 KiB。超长字段和预览均明确标记截断。大于 256 KiB 的报告交给共享的有界 CPU Worker 池解析。

`compilationVerified:false` 表示这不是完整编译；`ruleCoverageVerified:false` 表示原生报告未提供规则逐项执行回执。错误配置、缺失报告、损坏报告、执行失败分别返回明确错误，不能用空报告替代这些失败。

原生临时文件及日志定向到任务受管目录，预留 32 MiB；遵守共享存储预算和取消清理。SDK 退出后保留各已知引擎日志末尾最多 64 KiB，并注明原始长度和截断；原始进程日志也可用于失败核对。这是采样和超额取消机制，不是操作系统磁盘硬配额。

## 验证与限制

`test/native-lint.test.ts` 覆盖完整统计、Unicode 截断、原始制品、线程池、损坏输入、超额报告、路径逃出、显式外部配置、日志预算及失败退出码。`scripts/native-lint-acceptance.ts` 在新建专用工程中执行真实 SDK 验收。

2026-09-08，Studio 26.0.0.821 / SDK 26.0.0.105 的 6 项验收全部通过：干净工程、指定文件/配置及有界预览、显式修复后复查、损坏配置拒绝、非 Git 增量拒绝、已跟踪变更文件增量检查。证据：`/private/tmp/deveco-native-lint-20260908-3/evidence.json`，记录被测编译代码和资源摘要。

前两轮证据 `...-1/evidence.json`、`...-2/evidence.json` 保留失败：部分配置规则没有实际生效；原生解析器把损坏 JSON5 修复为空配置后返回成功。新实现增加调用前严格校验，但不能由此宣称所有未知规则都可检测。CLT 不同布局和外部 JDK 已有模拟回归，仍需更多真实组件及平台验证。以上验收没有构建、签名和设备操作。
