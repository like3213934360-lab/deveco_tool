# 同步和构建命令恢复

执行协议 `native-5`。`project_sync`、`project_build` 和 `build_deploy_verify` 的非热补丁构建接入 `ManagedCommand`。它使用现有 SQLite 操作记录和制品服务，不增加中间进程或独立任务管理器。

## 记录与核对

1. 命令发出前登记操作身份，绑定任务、图节点、阶段名称与完整命令摘要。摘要包含参数、工作目录和执行环境，保存记录不暴露环境值。输入或环境变化时拒绝接续，不静默更新已有任务。
2. SDK 子进程、拥有的后代和输出流全部确认关闭后，`ProcessService.onSettled` 调用领域收集函数。正常退出校验同步模型或构建制品；已确认的失败保存错误分类与诊断。
3. 结果和输出文件的大小、SHA-256 写入完成记录，再向调用方返回。超过 16 KiB 的结果保存为制品引用，单份完成记录的原始内容上限为 8 MiB，仍受全局存储预算约束。
4. 恢复先读取完成记录，核对文件类型、大小和摘要，再继续固定流程。已经完成的 OHPM 阶段不会再次安装依赖；尚未登记的后续 Hvigor 阶段可以开始。已确认的失败不会再次构建。

OHPM 记录工程中的依赖锁文件，同步记录实际 SDK 模型，构建记录实际制品。后续 HSP 构建可以更新工程模型，因此模型不作为前一次 HAP 构建的输出核对项。`build_deploy_verify` 将同步独立为图节点，各次构建保留自己的记录。

## 边界

- 宿主在命令完成记录提交前死亡时，记录仍不完整，任务保持 `needs_input`。旧文件存在或子进程已经退出都不足以证明命令成功，不盲目重跑。
- 已记录的制品被修改或删除时返回 `COMMAND_OUTPUT_CHANGED`，需要新任务，不能复用旧成功结果。
- 取消未确认所有进程退出时不调用完成钩子。长期会话不使用此一次性命令钩子；热补丁、设备和云端操作仍按各自协议核对。
- 这不是消除所有硬中断窗口的独立持久化执行器。真实 SDK 硬中断、安装准备、UI 逐步操作及其他领域恢复继续保留为单独验收项。

## 回归证据

`test/native-command-recovery.test.ts` 启动独立宿主和子命令，在子命令结束后、图节点提交前直接杀死宿主进程。覆盖同步后接续、构建成功、失败、大结果、完成记录缺失及同大小制品替换；恢复后执行计数必须仍为一次。

`test/native-project-recovery.test.ts` 通过真实 `ProjectService`、进程管理和 LangGraph，使用替代 SDK 命令验证 OHPM、同步和构建各阶段响应丢失，重开 SQLite 后不重复执行；构建失败产生超过输出尾部上限的日志，早期编译诊断仍可读取。这些回归不计为真实 SDK 中断证据。
