# 工作流制品归属与保留期

服务在工作流节点中生成的诊断报告、原生日志、API 扫描报告、截图、UI 树、热补丁回执等制品，使用当前追踪上下文的 `run_id` 登记。异步解析、原生临时目录作用域及设备排队必须保留该上下文；流式制品在创建流时固定归属。服务的独立调用仍按类别保存，按普通制品保留期清理。

`StateStore.artifact` 和 `streamArtifact` 的显式归属参数保持严格语义，不由环境上下文覆盖。工作流提交前的输入使用 `workflow-input` 暂存，再在创建任务的同一事务中转交；其他明确指定任务的检查点、日志和捕获文件也保持各自的归属。

复查发现，部分服务此前固定使用 `diagnostics`、`compatibility`、`ui` 等类别名，即使在工作流中也未登记实际任务。保留期清理会把这些制品当成无任务关联的过期记录，导致仍在等待输入或已中断的任务失去报告。这是新实现的缺陷，不是工程诊断错误。
