## 安装包占用问题的纠正

用户指出的问题属实：旧实现把每次部署的完整 HAP 长期当作证据保留，重复安装会累积占满 MCP 的磁盘状态配额。这不是电脑运行内存耗尽。此前“第七次被容量保护阻断，导出清理后恢复”仅证明保护和恢复通路有效，不代表保留策略合理。

现在 `app_deploy` 和 `build_deploy_verify` 在完整安装回执持久化后自动释放 MCP 拥有的临时副本，保留包摘要、字节数、回执和必要日志；安装结果未确定时继续保留恢复输入。项目自己的构建输出保持原样。删除失败仍记入配额并可在重启后补清理；后续启动失败恢复不会因为副本已释放而重复安装。

历史七次大包部署记录显示，结束后状态记账 4741912 字节，制品仅 3360 字节；累计部署 2363936561 字节，但完整包没有累积。事后导出 49 个制品、315 条事件和 7 条包释放记录，大小与 SHA-256 全部校验通过。重连后结果仍保留且没有完整安装包。独立默认 256 MiB 配置当时拒绝单个约 338 MB 的输入；单次输入也必须适配容量预算。这组原始证据现已丢失，以上数字仅是历史摘要，不能当作当前可复核的发布验收。
