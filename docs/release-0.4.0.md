# v0.4.0 发布说明

本次将完整领域 MCP 重构与工作流优化代码汇入 main。版本为 0.4.0，协议为 native-7。

## 主要变化

- 宿主负责推理、业务文件编辑及视觉判断；MCP 提供原生工具、固定工作流、恢复与可核对的证据。
- 工作流支持有界等待、精简状态、完整结果分页和具体恢复入口；新增普通构建运行与成功构建引用。
- 工程创建支持空目录、显式安全合并、默认 SDK 选择和可复用工程描述符。
- 构建保留完整 ArkTS 预检，依赖和模型身份一致时复用同步；诊断保留位置、来源、原报告和案例引用。
- UI 计划可直接初始化，动作后可检查当前步骤，待审阅截图直接经 MCP 交付；录制与逐需求验收均按需使用。
- 历史崩溃诊断引用原任务证据；构建、部署、UI 与验收传递已有引用，并说明证据失效范围。
- 原生 LSP、启动检查、连续日志、录制隐私、升级/回退及运行时遥测的既有未提交改动一并纳入。

迁移说明见 [领域协议迁移](domain-protocol-migration.md)。全部 37 项优化与评估见 [工作流 TODO](refactoring/2026-09-15-workflow-optimization-todo.md)。

## 发布与验证范围

本版本按仓库所有者确认的“已验证范围”推进正式发布，公开范围见 [publication-scope-0.4.0.json](../provenance/publication-scope-0.4.0.json)。发布附件 `acceptance.json` 绑定最终 main 提交、源码/编译产物/依赖/资源身份及 ZIP 摘要；`passed` 只表示其中声明的 `verified_source_and_installation` 范围，`full_acceptance` 为 `false`。

发布前须通过严格编译、资源校验、macOS / Linux / Windows × Node 22 / 24 的六组回归和干净安装、两个 Windows 进程压力检查、本机实际 Studio SDK 检查，并核对六组分发清单一致。最终计数、CI 链接和摘要以 Release 附件为准。

## 明确限制

当前完整 `release-gate` 尚未满足：上游接受记录缺失或过期，28 行迁移仍为 pending，48 项专项验收和 19 项性能能力的完整当前矩阵尚未齐备。真实设备、多显示器、更多 SDK/CLT 与操作系统组合、云端签名及过期认证等具体范围见 [待验收清单](release-0.4.0-readiness.md)。历史 SDK/设备报告、模拟适配器测量与单元回归不替代这些验收；完整发布门禁未被标成通过。

仓库所有者于 2026-09-15 明确取消一小时混合稳定性测试及随后的空闲回收证据作为本版本发布门槛。运行时日志打点和按需稳定性测试工具保留；公开记录为 `cancelled_by_user`，不声称稳定性已通过。

本次按上述范围直接发布带摘要和公开回执的编译包。既有全量 `release-evidence` / `release` 流程和严格策略保留，完整验收后仍可使用；本次不声称已通过该流程。
