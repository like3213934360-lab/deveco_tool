# v1.4.6 OpenCode 模型验收

本轮沿用 OpenCode 1.18.35、现有登录/提供商、指定 USB 真机和原 SDK。`tools/model-eval.mjs`、`tools/model-matrix.mjs` 的严格评分、10 分钟单轮期限、允许工具及场景匹配规则均未改变。没有修复模型输出 JSON、删掉失败调用或以纠正后的成功覆盖首次失败。

完整的脱敏逐轮结果、不可变构建 ID、原始请求/响应及 transport 哈希见[证据 JSON](evidence/v1.4.6-models.json)。原始文件在私有 `.scratch/remaining-audit`，包括历史错误，不上传登录信息、设备日志和源码路径。

## 三种证据分别统计

1. **拟调用发现**：103 个场景覆盖 102 个 action（另含非法端口澄清场景）；Muse Spark 1.3 与 MiMo V2.6 Flash 各两轮，每轮分 26/26/26/25 四批。仅检查模型计划，实际 MCP 调用数为 0。v1.4.5、v1.4.6 中间稿、最终构建分别运行，不把中间构建当最终版本。
2. **11 免费模型基础实际调用**：两轮 × 5 场景，环境/USB 信息、知识库目录和离线状态、Skill 列表及读取、developer 登录状态。模型目录当时显示零成本且支持工具；目录可见不保证服务端仍可用。该组固定中间构建 `3ec0a096...`，不是最终构建的替代证据。
3. **最终构建 USB 实际调用**：Muse、MiMo、Big Pickle 各两轮 × 17 场景，12 类工具，包括测试应用 stop/launch、窗口、树、找元素、断言、点击及 Welcome 结果。全部限定专用应用与 USB 连接。auth/sign/hot_reload 的写入路径由本轮及前轮确定性实际验收覆盖，不声称这 17 个模型场景等于所有写入功能。

所有场景均为文本可完成，不要求非多模态模型读取图片；本轮模型结果也不证明视觉 review 能力。此前人工看图后的原生 review 是另一种证据。

## 归因

| 现象 | 可以确认的原因及边界 |
| --- | --- |
| exo-free 在 MCP 调用前失败 | 提供商 HTTP 410 / ModelDeprecated；不是 MCP 工具失败 |
| ling-3.0-flash-fin-free 在 MCP 调用前失败 | 提供商 HTTP 400 / Model is unavailable；目录仍可见不等于可调用 |
| ling-3.1-flash-free 部分调用后中断 | 首轮提供商 HTTP 429 / Endpoint is unavailable；已完成调用保留，但整轮失败 |
| 拟调用结果不能解析 | 模型生成的原始 JSON 不合法或额外转义；未做修复后重评 |
| 非法端口仍计划调用 | [实际出站 schema](evidence/v1.4.6-provider-schema.json)中，Muse 路径去掉 minimum/maximum，MiMo 路径保留；两者均收到文本范围及先澄清要求。前者存在宿主适配层数值约束丢失，后者仍错说明不能只归咎于 MCP schema。服务端验证仍严格拒绝非法值 |
| review 先凭空填 id/结论 | 已明确首次只取图、检查图片后使用返回的 review_id；在模型实际收到新描述后仍有错误。说明已可见，但描述不能保证所有模型遵从；不补默认 id 或自动判通过 |
| 漏 action、漏 limit/offline 等参数 | 原始提供商响应/transport 证明模型没有执行要求的调用，或把不存在的 `file` 传给 check（应为 `files`），catalog 传了不存在的 `all`。MCP 明确拒绝错误，未静默适配 |
| 纠正后自称“全部完成” | 真实错误和缺失仍使严格评分失败；模型摘要不作为断言 |
| Big Pickle 首轮 USB 场景超时 | 10 分钟原限额内仅发出并完成 6 个 MCP 调用，最后两次设备调用分别约 120/119 ms；之后未发出 MCP 请求，也无挂起工具响应。阻塞位于模型/提供商/宿主生成链路，当前证据不能进一步区分网络或服务端原因 |
| UI find 的 HDC 超时 | 一次真实 30 秒超时，空 stdout/stderr；相邻 tree 及之后 assert/click 成功。日志查询没有捕获对应诊断，不能据此确定 USB、HDC 服务或设备 UiTest 的具体根因，也不能归为模型传参错或确认已修复；模型全部结束后相同 tree/find/assert 顺序 10 轮（30 次 UI 调用）通过，最大 1,136 ms，原失败不改记 |

参数匹配还有已独立证明的等价路径：单实例 `name` 与 `names:[name]`、源码相对与绝对路径、tree 缺省 depth 与 0。模型旧评分仍保持失败，旁注实际等价，不把放宽评分用作“修复”。相反，遗漏 offline、改变日志条数/时间窗、跳过 windows、在首轮取图时填写结论等未被当成等价。

## 结论与待办

已确认工具能通过 OpenCode 读取实际 SDK 版本信息、执行静态检查和只读查询，以及操作真机界面，也确认部分免费模型存在服务可用性、遗漏、参数和输出格式问题。现有证据不支持“所有免费模型全部功能稳定可用”。必要说明已补齐；没有以继续增加重复文本、放宽参数校验或自动换模型掩盖问题。
