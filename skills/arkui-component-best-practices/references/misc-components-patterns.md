# 低频组件兜底模式

## 什么时候使用

当搜索结果没有命中其他专门 reference，或组件文章数量很少时读本文件。它不是优先入口，只用于兜底。

当前 405 篇索引已经尽量把文章分到具体二级场景；如仍落到本文件，先运行：

```bash
node scripts/search-practices.mjs <组件名或场景词>
```

再打开 `article-coverage-map.md` 看同类文章。

## 处理原则

- 先判断这个组件是输入、展示、布局、导航、反馈还是原生桥接。
- 如果能归入已有 reference，优先读已有 reference。
- 如果确实是低频组件，只抽取文章中的触发场景、状态模型、关键 API、常见坑。
- 不要为了一个低频组件把全文加入 `SKILL.md`。

## 回答用户时应包含

1. 该组件属于哪类 UI 责任。
2. 是否已有相近 reference 可以复用。
3. 当前文章给出的关键实践点。
4. 官方链接，便于继续溯源。
