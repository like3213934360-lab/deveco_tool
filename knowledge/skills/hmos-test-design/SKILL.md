# 鸿蒙测试设计

优先使用鸿蒙官方测试能力，复用现有测试和入口。优先通过 DevEco MCP 获取环境信息并执行测试，未覆盖的操作使用工程工具链。

按所选路线读取[测试执行要点](references/harmonyos-testing.md)的相关部分。API、配置或命令不确定时，通过项目 SDK／依赖、DevEco MCP 或官方文档核实。

## 选择测试方式

| 目标 | 优先路线 |
|---|---|
| Stage 工程中 Local Test 支持的 ArkTS 逻辑 | Hypium + Local Test |
| 真实系统 API、持久化、生命周期或平台集成 | Instrument Test |
| UI 交互 | Instrument Test + UiTest |
| 代码段或 PerfTest 支持的场景性能 | Instrument Test + PerfTest；其他性能目标选择对应专项工具 |
| C++／NAPI | Instrument Test 的原生测试入口，复用已有测试设施 |

Hypium 指 `@ohos/hypium`；Local／Instrument 是运行方式，不等同于单元／集成测试的划分。

## 编写用例

- 按需求覆盖相关的正常、边界、错误和状态转换，断言可观察结果；预期来自需求或独立样本，不复制实现算法。
- Mock 只替换依赖，不替换被测行为；需要证明真实系统或集成行为时，使用实际依赖。
- 用例相互独立并清理资源；异步设置超时并等待业务完成，UI 使用稳定选择器和条件等待。
- 回归用例尽可能验证修复前失败、修复后通过；不通过削弱断言或改变业务规则换取通过。

## 执行与交付

- 确认目标用例已注册、被发现并实际执行；构建成功、应用启动或零用例不算测试通过。
- 根据报告区分测试失败、运行错误、跳过和环境阻碍；结论仅覆盖实际运行的环境与依赖。
- 简要报告实际执行方式与环境、测试结果、报告位置及未验证项。
